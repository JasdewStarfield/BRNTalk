# BRNTalk Roadmap

当前版本基线：`1.1.1`

## 定位

- 面向 RPG 服务器、任务地图和整合包的剧情对话模组。
- 以服务端驱动、多人同步、热重载和双版本维护为核心。
- 长期目标是成为可复用的剧情对话基础设施，而不只是一个聊天 UI。

## 路线原则

1. 先补稳定性，再补大功能。
2. 先补作者工作流，再补复杂表现层。
3. 优先做可复用的平台能力，少做一次性特化逻辑。
4. 服务端行为开关优先走 `serverconfig`。
5. 功能开发默认先落在 `mc/1.21.1-neoforge`，再按可移植粒度同步到 `mc/1.20.1-forge`。

## 当前判断

- `1.1.0` 已完成双版本维护、平台层整理和 1.20.1 Forge 适配。
- `1.1.1` 已处理近期 UI、滚动、本地化和缓存类问题。
- 现在可以进入 `1.2.0` 开发，但应把它定义为作者体验和验证能力版本，而不是大规模剧情语义升级。
- 客户端结构拆分仍然重要，但更适合作为 `1.3.0` 的主线。

## 1.1.x：稳定维护线

### 目标

- 保持双分支发布稳定。
- 快速修复用户可见 bug。
- 避免把新语义塞进 patch 版本。

### 任务

- 小范围 UI / HUD / Toast 修复。
- 双语翻译文本补齐。
- 发布脚本和平台 metadata 修补。
- 双分支 changelog、README、版本号同步。
- 发布前继续执行：
  - `git diff --check`
  - `.\gradlew.bat build --no-configuration-cache`

## 1.2.0：作者体验与验证能力

### 目标

- 让服务器作者更容易编写、检查和调试对话脚本。
- 给后续条件、变量、动作系统升级补上测试和诊断基础。
- 不引入会破坏旧脚本的大型 DSL 改动。

### 模组内修改

- 增强脚本校验报告：
  - 尽量定位到文件、剧本 ID、消息 ID、choice ID。
  - 区分错误、警告和建议。
  - 继续阻止严重错误脚本进入运行时。
- 扩展校验规则：
  - 无法到达的消息节点。
  - 重复 choice ID。
  - 空文本或仅空白文本。
  - `wait` 节点恢复目标不明确的风险。
- 改善 `/reload` 后的 OP 提示：
  - 摘要仍保持简短。
  - 详情行更适合直接回到脚本文件定位。
- 梳理 `BrntalkAPI` 和事件边界：
  - 明确哪些方法是稳定 API。
  - 明确 `PlayerSeenMessageEvent` 的触发语义。
  - 为后续联动事件预留扩展点。
- 补运行时防护：
  - 防止异常脚本状态造成无限推进。
  - 对 `action` 执行失败给出更清楚的日志。
  - 保持旧脚本兼容。

### 外部程序、脚本和文档

- 第一阶段执行清单见 [`EXTERNAL_VALIDATION_PLAN.md`](EXTERNAL_VALIDATION_PLAN.md)。
- 补第一批自动化验证入口：
  - 脚本校验用例。
  - `wait` 恢复用例。
  - `action` 执行用例。
  - 基础同步或重载 smoke 用例。
- 整理 `validation_fixtures`：
  - 无效脚本 fixture 覆盖常见错误。
  - 增加有效脚本 fixture 作为 smoke 输入。
  - 每个 fixture 写清预期结果。
- 增强 `tools/debug`：
  - 一键注入 fixture。
  - 一键读取 BRNTalk 相关日志。
  - 输出 pass / fail 摘要，而不只是原始日志。
- 更新作者文档：
  - 推荐脚本写法。
  - 常见错误排查。
  - `/reload` 校验报告解释。
  - 双语 README 中同步当前脚本能力。
- 视情况补 GameTest 或轻量测试任务：
  - 优先覆盖纯校验逻辑。
  - 再覆盖需要游戏环境的运行时流程。

## 1.3.0：客户端结构与长对话体验

### 目标

- 降低 UI 维护成本。
- 改善长对话、多线程和未读状态体验。

### 任务

- 拆分 `TalkScreen`：
  - 主屏幕编排。
  - 线程列表。
  - 聊天内容布局。
  - 选项按钮区域。
  - 滚动状态。
- 拆分 `ClientTalkUtils`：
  - 文本处理。
  - 时间轴计算。
  - 预览文本生成。
  - 渲染缓存。
  - 通用绘制工具。
- 优化线程列表与未读状态。
- 继续打磨长对话滚动、预览和打字机表现。
- 视实际反馈评估：
  - 搜索消息。
  - 重要消息置顶。
  - 对话分组。

## 1.4.0：联动 API 与动作系统

### 目标

- 让其他模组、任务系统和数据包更稳定地接入 BRNTalk。
- 把现有单条 `action` 的能力升级成更可扩展的动作边界。

### 任务

- 增加更合适的联动事件点。
- 评估 KubeJS、任务系统、命令编排的支持方式。
- 设计更正式的动作系统：
  - 多动作。
  - 条件执行。
  - 失败日志。
  - 权限和安全边界。
- 保持旧 `action` 字段兼容。

## 1.5.0+：剧情平台能力

### 候选方向

- 条件节点。
- 变量与标签系统。
- 更丰富的消息载体。
- 更稳定的跨模组集成协议。
- 脚本迁移和版本标记。

## 2.x：破坏性格式升级保留位

- 只有在脚本格式、条件表达式或运行时状态需要破坏性升级时才进入 `2.x`。
- 不为了普通功能堆叠而提前使用 `2.0`。

## 暂不优先

- 大规模视觉重做。
- 过早引入复杂剧情 DSL。
- 在缺少测试前提下做大范围重构。
- 为了堆功能而加入低复用特殊节点。
- 将 `1.2.0` 同时做成作者体验、UI 重构、动作系统三合一版本。
